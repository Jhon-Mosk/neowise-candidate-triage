# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Тесты

Встроенный раннер Node.js, без зависимостей:

```sh
node --test          # или npm test
```

Тесты в `test/triage.test.mjs` поднимают сервер на свободном порту и проверяют:

- некорректный ввод (пустое тело, битый JSON, `null`, массив, нет `text`, не строка, пустая строка, одни пробелы) → `400 {"status":"invalid_input"}`;
- все сценарии сбоя имитатора (`[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`) → `200 manual_review` с `topic: null` и `draft: null`;
- таймаут укладывается в 300 мс, даже если модель игнорирует сигнал отмены;
- в лог пишется причина сбоя, но не текст заявки;
- экран менеджера (`view.mjs`): при любом ответе, кроме `ready`, — сообщение о ручном разборе и пустой черновик.

Ручная проверка: `node server.mjs`, затем на странице отправить «Когда доставка?» (тема и черновик), потом «Заявка [bad-topic]» — черновик исчезает, видно сообщение о ручном разборе.

## Устройство

| Файл | Что делает |
| --- | --- |
| `server.mjs` | `parseInput` — проверка ввода; `callModel` — ожидание модели не дольше 300 мс (`AbortController` + гонка с таймером); `parseModelOutput` — проверка ответа модели (JSON, тема из списка, непустой черновик). Любой сбой → `manual_review` и запись в лог |
| `view.mjs` | чистая функция `toView`: что показать менеджеру по ответу API |
| `index.html` | форма; при отправке сразу очищает прошлый результат, отменяет предыдущий запрос и игнорирует устаревший ответ |
| `mock-ai.mjs` | имитатор модели — без изменений |

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.
